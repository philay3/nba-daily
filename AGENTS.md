# AGENTS.md

Guidance for coding agents (and humans) working in this repo.

## Scope

NBA Daily is Chops's data and graphics app for NBA videos and social posts.

- A Python pipeline fills Postgres once a day: every regular-season box score so far (ESPN data via the hoopR mirror), team and player season stats with league ranks, per-game four factors, team-vs-team gap significance, player deltas vs pre-game averages, every field goal attempt with its spot and zone plus zone profiles, tonight's schedule, odds, injuries and editorial picks.
- A Next.js app reads Postgres and shows Today, game pages, teams, players, standings and injuries.
- `/studio` renders fixed-size graphics from the same data and exports PNGs for posts (1080x1350 feed, 1080x1920 story, 1920x1080 YouTube).

In v1: regular season only (`season_type = 2`), one season per run (`--season`), no auth, no deploy scripts, no AI-written notes (the editorial provider is a no-op with a TODO for the Claude API), no play-by-play beyond the shot file.

## Architecture

```
hoopR mirror (parquet, daily 07:00 UTC) ─┐
raw per-game mirror / PATCH files ───────┼─> nba_pipeline.sources ─> compute ─> load ─> Postgres ─> web (server components)
ESPN odds + injuries (unofficial JSON) ──┘                                         │
inputs dir (odds/injuries/editorial JSON) ─────────────────────────────────────────┘─> export-json (dashboard files), digest
```

- `pipeline/nba_pipeline/compute.py` is a faithful port of the original engine (`nba_build.py`). The math (possessions, ratings, pace with overtime, four factors, ranks, gap z-scores, flags) must not change without updating the golden files on purpose.
- `pipeline/nba_pipeline/export.py` turns database rows into the ten dashboard JSON files. The same function runs on in-memory rows (fast parity test) and on rows read back from Postgres (full-chain parity test).
- Schema source of truth: `web/src/db/schema.ts`. Migrations: `web/drizzle/*.sql`, generated by drizzle-kit and applied by either `npm --prefix web run db:migrate` or `python -m nba_pipeline migrate` (same journal table).
- Season tables (`team_season`, `player_season`) and per-game derived tables (`game_gaps`, `player_game_deltas`) are rebuilt for the whole season on every run. Facts (`games`, `team_games`, `player_games`) are upserted; `shots` are rewritten per game when that game's shots change. Snapshots (`injuries`, `odds`, `editorial`, `game_previews`) are replaced for the run date.
- Pipeline map: `sources/` (hoopr, raw, patch, espn, inputs) -> `compute.py` -> `run.py` (inputs, editorial, checks) -> `previews.py` (the 3-day look-ahead) -> `shots.py` (attempts, zones and zone profiles from the shot file) -> `load.py`; `export.py`, `digest.py`, `checks.py` work on the same `tables` dict; `db.py` connects and migrates; `cli.py` is the entry point.
- Web map: `web/src/app/(site)/...` pages (server components), `web/src/app/(bare)/studio/frame` (one graphic at full size, no site chrome), `web/src/lib/data.ts` (all queries), `web/src/components/charts` (SVG charts, including the half-court `ShotChart`), `web/src/lib/shots.ts` (shot chart math: zones, hex bins, tooltips; no imports, tested with `npm --prefix web test`), `web/src/components/studio/templates.tsx` (the five graphics; pure components so the preview, the frame route and the PNG export match).

## Commands

In a Claude Code cloud session there is no Docker database running and no `.env`: follow the setup in [docs/cloud-tasks.md](docs/cloud-tasks.md) instead of `docker compose`. That file also holds the queued tasks.

```bash
cp .env.example .env                 # one env file for pipeline and web
docker compose up -d db              # Postgres 16 on localhost:5432
python3 -m pip install -e "pipeline[dev]"
npm --prefix web ci

python3 -m nba_pipeline migrate      # apply web/drizzle migrations
python3 -m nba_pipeline seed         # offline fixture day 2026-11-02 + golden inputs
python3 -m nba_pipeline run --date 2026-11-03 [--source-dir DIR] [--inputs DIR] [--no-espn] [--season 2027]
python3 -m nba_pipeline digest --date 2026-11-02
python3 -m nba_pipeline export-json --date 2026-11-02 --out exports/2026-11-02
python3 -m nba_pipeline record-fixtures --date 2026-11-03 --out pipeline/fixtures/espn_live

cd pipeline && python3 -m pytest -q  # parity, ESPN parsers, DB load (DB tests need DATABASE_URL)
npm --prefix web run dev             # http://localhost:3000
npm --prefix web run typecheck && npm --prefix web run lint && npm --prefix web test && npm --prefix web run build
NODE_PATH="$(npm root -g)" npm --prefix web run smoke   # Playwright smoke test against BASE_URL (default http://localhost:3000)
SCREENSHOTS=1 DATE=2026-11-02 GAME_ID=401909906 PLAYER_ID=3945274 NODE_PATH="$(npm root -g)" npm --prefix web run smoke   # also refresh docs/screenshots
npm --prefix web run db:generate     # after editing web/src/db/schema.ts
```

Run Python that reads downloaded data with `python3 -I` in shared or sandboxed environments.

## Conventions

- snake_case for SQL columns, Drizzle keys, Python and JSON fields. Team codes are ours (`GSW`, `NYK`, `NOP`, `SAS`, `UTA`, `WAS`); ESPN's (`GS`, `NY`, `NO`, `SA`, `UTAH`, `WSH`) are mapped at the source boundary.
- Dates: `game_date` and snapshot dates are America/New_York calendar dates. Tip times are `timestamptz` in UTC.
- Ranks: 1 = best; for pace 1 = fastest. Volume stats (attempts) have no "better" side.
- Stats stored at display precision (one decimal, `z` two decimals), exactly like the original engine's JSON.
- Web pages are server components that query through `web/src/lib/data.ts`; client components only for interaction (sorting, pickers, studio export).
- Charts are hand-built SVG with D3 scales (`web/src/components/charts`). No chart libraries.
- UI and graphic copy: plain words, short sentences, no em dashes.
- Commit in small chunks with imperative messages.
- `web/AGENTS.md` is written by `next dev` (Next.js 16 agent notes); leave it committed. Next.js 16 docs ship in `web/node_modules/next/dist/docs/`.

## Things not to do

- Do not change formulas in `compute.py` to make a test pass; the golden files in `pipeline/fixtures/golden_2026-11-02` are the reference output of the original engine, plus the deliberate fixes in `docs/DECISIONS.md`. After a deliberate change, `cd pipeline && python3 -I tests/regen_golden.py` rewrites them and lists every field that changed.
- Do not edit generated migrations by hand; change `schema.ts` and run `npm --prefix web run db:generate`.
- Do not call ESPN or the mirror from tests. Tests use `pipeline/fixtures` only.
- Do not use NBA or team logos, or player photos (trademark and copyright). Use team codes, names and colors.
- Do not add Prisma, a chart library, or `next/font/google`.
- Do not commit `.env` or real credentials. The daily workflow reads `secrets.DATABASE_URL`.
- Do not add playoffs or play-in handling without a plan: the engine filters `season_type == 2`.
